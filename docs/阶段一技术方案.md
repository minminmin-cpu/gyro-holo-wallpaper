# 阶段一技术方案：陀螺仪驱动的闪光跟随动态壁纸

> 版本：stage1-1.0.0 · 2026-11-12
> 范围：基于 RuiC-card-skill 的材质/视差技术，结合手机陀螺仪，做一张闪光随视角游走的动态壁纸。
> 阶段二路线后来改为「Android App + 内置 Live Wallpaper（免费开源）」，见 `docs/阶段二技术方案.md`；本文只记录阶段一。

---

## 1. 目标与技术路线

一句话目标：**把 RuiC 闪卡里「拖拽相机 → 镭射相位与分层景深跟着变」的那套机制，
换成「手机姿态 → 同样的 uView」，并把 3D 卡片几何降级为全屏 quad 以便长期常驻。**

```
手机姿态（欧拉角 / 四元数 / 指针）
   │  权限 → 坐标归一化 → 校准 → 阻尼滤波
   ▼
uView = normalize(vec3(tx, ty, 1))
   │
   ├─ 视差   parallax(uv, depth) = uv + uView.xy / max(|uView.z|, 0.4) * depth * 0.10
   ├─ 镭射   film(uv) 相位含 uView.x*1.5 - uView.y*0.9
   ├─ 扫光   sweep(uv) 相位含 uView.x*1.2 + uView.y*0.6
   └─ 新增   glintCenter = 0.5 + uView.xy * uGlintRange（镜面高光游走）
   ▼
WebGL1 单 draw call / 5 张纹理 → 全屏壁纸（WebGL 不可用时 CSS-3D 兜底）
```

**为什么不用 three.js 重写场景**：RuiC 原网页是 3D 卡片（几何体 + 4 种材质槽 + glTF），
壁纸只需要「平面分层 + 视角相关着色」。把 5 层采样合并进一个片元着色器后，
从 N 个 draw call 降到 **1 个**，这是长期常驻、耗电敏感场景下最关键的一步。
着色器公式仍逐行移植自 `assets/web-template/app.js`，视觉语言保持一致。

## 3. 开源库选型与理由

### 3.1 调研结论（含真实性核实）

| 项目 | 状态 | 结论 |
|---|---|---|
| [`adtile/Full-Tilt`](https://github.com/adtile/Full-Tilt)（v0.7，亦称 ustwo/Full-Tilt、richtr） | 2015 年后停更 | **只借鉴算法**：它把 iOS/Android 的欧拉角归一化成 screen-adjusted 四元数/矩阵，并处理横竖屏。不引入运行时（Bower 时代产物、无 iOS 权限处理）。 |
| [`dorukeker/gyronorm.js`](https://github.com/dorukeker/gyronorm.js)（v2.0.6） | 作者已宣布停止维护 | **只借鉴思路**：`game`/`world` 双参考系、重力归一化、滑动均值滤波。内部打包了 FullTilt。 |
| [`kenchris/sensor-polyfills`](https://github.com/kenchris/sensor-polyfills)（BSD-3，npm `motion-sensors-polyfill` 0.3.7） | 约 4 年前停更 | **实际引入，但仅作可选通道**：已把 `src/motion-sensors.js` + `src/sensor.js` + LICENSE 放进 `vendor/`，加 `?sensor=polyfill` 才动态加载。 |
| [`mrdoob/three.js`](https://github.com/mrdoob/three.js) | 活跃 | 渲染思想来源；但 **`DeviceOrientationControls` 在 r134 已被移除**（见官方 Migration Guide 133→134），不能当现成控件用。 |
| `@vueuse/core` 的 `useDeviceOrientation` | 活跃 | 若阶段二改成 Vue 技术栈可用；本项目零框架，不需要。 |
| `ionic-team/capacitor-plugins` 的 `@capacitor/motion` | 活跃 | 若改用 Capacitor 打包原生 App 可用；本项目直接走原生 `WallpaperService`，不需要。 |
| [`hanschencoder/GLWallpaperService`](https://github.com/hanschencoder/GLWallpaperService) | 参考基座 | 把 `GLSurfaceView.Renderer` 桥接到 `WallpaperService.Engine`，是 Android 真·系统壁纸最省事的起点。 |

### 3.2 最终选型：**运行时零第三方依赖，polyfill 可选**

| 层 | 选择 | 理由 |
|---|---|---|
| 主传感器通道 | 原生 `DeviceOrientationEvent` | iOS / Android / 各大 WebView 全支持；无需打包；权限与滤波完全可控 |
| 增强通道 | 原生 `RelativeOrientationSensor`（Chromium 原生，Chrome 67+ / Edge 79+ / Android WebView 67+） | 直接给四元数，规避欧拉角万向锁与 alpha 跨圈跳变，可指定 `frequency: 60` |
| 兼容通道 | `kenchris/sensor-polyfills` | 把 `deviceorientation` 包装成同一套 `Sensor` 接口，便于未来统一；其源码是 `window.RelativeOrientationSensor \|\| class...`，**优先复用原生、不会覆盖浏览器实现** |
| 归一化/滤波 | 自写 `src/math.js`（约 130 行） | FullTilt/gyronorm 都停更多年且不含 iOS 权限逻辑；核心算法只需角度差、屏幕旋转、四元数共轭、指数阻尼，自写反而更小更可控 |
| 渲染 | 原生 WebGL1 | 1 draw call；不引入 three.js 的场景图开销 |
| Android 系统壁纸 | `WallpaperService` + `SensorManager.TYPE_GAME_ROTATION_VECTOR` + GLES20 | 无第三方依赖、无定位权限、不受磁场干扰 |

**为什么不把 FullTilt / gyronorm 直接装进来**：两者都是 2014–2018 年的 Bower 时代代码，
没有 `requestPermission()`、没有 `visibilitychange` 生命周期、没有 `screen.orientation` 的现代处理，
上游 README 还记录了 polyfill 在 iOS 倒置方向会 180° 翻转的已知缺陷。引入它们等于把
最难的那部分兼容工作重新背回来。因此策略是「**算法照抄、运行时自写、polyfill 可插拔**」。

## 4. 关键实现步骤

### 4.1 陀螺仪数据采集（`src/gyro.js` + `src/math.js`）

**三条通道自动选择**：

```
iOS / Safari ──────────────► deviceorientation（唯一可靠通道）
Android Chromium ──────────► 原生 RelativeOrientationSensor（四元数）
?sensor=polyfill ──────────► vendor/sensor-polyfills 的动态 import
无传感器 / 桌面 ──────────► 指针拖动 + 自动巡游
```

**授权**：`requestPermission()` 在按钮 `click` 的同步调用栈内触发；`DeviceMotionEvent`
的授权失败不阻断（方向事件不依赖它）。

**坐标归一化**（这是跨端最容易翻车的一步）：

1. 校准：首次采样把当前姿态记为中性点 `base`，之后一律输出**相对量**——用户平躺、
   坐着、举着手机都能得到一致的「居中」效果；提供「校准中性姿态」按钮随时重设。
2. 跨圈跳变：`angleDelta(a,b)` 用 `(a-b) % 360` 再折回 `(-180,180]`，处理 alpha 从
   359° 跳到 1°。
3. 横竖屏：`deviceTiltToScreen(gamma, beta, screenAngle)` 按 `screen.orientation.angle`
   做 2D 旋转；老 WebView 回退 `msOrientation` / `window.orientation`。
4. 轴符号：部分 Android 机型 gamma 方向与 iOS 相反，暴露 `invertX/invertY` 开关，真机标定即可。
5. 四元数通道：`rel = conjugate(inverse(baseQ) * q)` 作用于局部 +Z，
   **严格对齐 RuiC 的 `camera.position.applyMatrix4(root.matrixWorld.invert())`**，
   保证两条通道产生同方向的视角变化。

**滤波**（`DampedView`）：帧率无关的一阶指数阻尼

```
a = 1 - exp(-dt / tau)          tau 默认 0.11s
v += shrink(target - v) * a     shrink = 死区(0.6°) 内返回 0
```

`dt` 参与计算，因此 30fps 与 120fps 设备手感一致；死区抑制静止时的高频抖动。
传感器事件只更新 `target`，**绝不在回调里改 DOM 或渲染**，所有视觉更新收敛到 `requestAnimationFrame`。

### 4.2 闪光跟随算法（`src/holo-shader.js`）

**从 RuiC 原样移植**（系数不改）：

```
parallax(uv, depth) = uv + uView.xy / max(|uView.z|, 0.4) * depth * 0.10
spectrum(p)         = 0.66 + 0.25 * cos(2π * (p + vec3(0, .33, .67)))
film(uv).phase      = uv.x*.85 + uv.y*.55 + uView.x*1.5 - uView.y*.9
sweep(uv).phase     = uv.x*.72 + uv.y*.45 + uView.x*1.2 + uView.y*.6
```

`max(|uView.z|, 0.4)` 是原作者防除零爆炸的下界，务必保留。四层合成顺序仍为
`background → subject(alpha) → effects → foil → edge → flake → lineart glow → text`，
文字层不做视差，卡框稳稳钉在边缘。

**新增的两处「闪光跟随」**：

```
glintCenter = vec2(0.5) + uView.xy * uGlintRange        // 高光中心随手机倾斜游走
r           = length((uv - glintCenter) * uAspect)      // 按屏幕比例校正，避免椭圆失真
glint       = exp(-r² / uGlintSigma²)
col        += spectrum(phase + r * 1.2) * glint * foilStrength * uGlintGain
```

`phase + r*1.2` 让高光边缘出现由近及远的彩虹色散；`uAspect = [w/max(w,h), h/max(w,h)]`
保证竖屏下高光仍是物理圆形。另有沿视线偏移的轻微软重影 `ghost`（为阶段二的「闪光重影」
预留参数，阶段一默认 0.18，可调到 0 关闭）。

> **一个刻意保留的设计**：RuiC 的 SKILL.md 明确警告「镭射相位如果只由时间驱动，
> 看起来就是循环视频而不是箔」。因此 `uTime` 在本项目里**只推星点闪烁**，
> 所有主要相位都由 `uView` 驱动。这正是「闪光跟随手机」而不是「自动播放动画」的区别。

**uView 映射**：

```
tilt ∈ [-maxViewXY, maxViewXY]  →  uView = normalize(vec3(tilt.x, tilt.y, 1))
```

z 恒正且接近 1，与原网页相机位于卡面正前方一致；`maxViewXY = 0.78` 限制极端倾角，
避免视差把主体推出画面。

### 4.3 壁纸渲染（`src/renderer.js` + `src/main.js`）

- **一个全屏 quad、一次 `glDrawArrays`、5 个纹理单元**（GLSL ES 1.00，WebGL1/2 通吃）。
  原 three.js 版本末尾 `pow(col, 2.2)` + `<colorspace_fragment>` 是一次 sRGB↔linear 往返，
  净效果近似恒等，脱离 three 后直接输出 `col`，观感保持一致。
- **素材契约沿用 RuiC**：`subject.png`(RGBA) / `background.png`(不透明) /
  `lineart.png`(白底黑线) / `text.png`(RGBA) / `effects.png`(可选 RGBA)，
  统一 1024×1536。本项目用 `tools/generate_assets.py` 程序化生成一套确定性演示素材，
  可直接用 RuiC 的 `validate_assets.py` 校验。
- **省电策略**（壁纸最关键的工程约束）：
  - DPR 上限 1.75，`powerPreference: "low-power"`；
  - 静止时自动从 60fps 降到 12fps（`stillEpsilon` 判定），倾斜时立刻恢复；
  - `document.hidden` 停渲染、`visibilitychange` 停/启传感器；
  - 传感器 60Hz 事件节流，视觉只在 rAF 更新；
  - `prefers-reduced-motion` / 无 WebGL → CSS-3D 分层 + 径向渐变高光兜底。
- **单文件分发**：`tools/build_standalone.py` 把 6 个 ESM 模块去 import/export 后按依赖序
  拼接，并把 5 张 PNG 内联为 data URI，产出 `standalone.html`。
  这样 `file://` 直开也不会因 CORS 导致 `texImage2D` 失败。
- **自动化钩子**：`window.__holoWallpaper` 提供 `getState / setView / setParameter /
  setFinish / capture / setMotion`，对齐 RuiC 的 `window.__holo`，便于 headless 像素对比与第二阶段导出。

### 4.4 与官方演示的视觉对齐（实证比对）

不靠文字推测，直接把技能仓库自带的 **`demo-after.gif`（135 帧）/ `demo-before.gif`（161 帧）**
抽帧放大比对：`tests/demo-after-*-zoom.png`、`tests/demo-timeline.png`。观察到：

1. **闪光形态**：覆盖整张卡面的暖金/彩虹箔光 + 斜向扫光带；卡片边缘有金色反光；
   高光最亮处随视角在卡面上移动。**不是**孤立的圆形聚光灯。
2. **重影本质**：主要是**空间分层错位** —— 主体（含溢出的墨迹/发丝）浮在卡框之外，
   线稿、特效与主体按不同深度错开；连续 6 帧时间轴里**没有**明显的帧间拖影累积。
3. **构图**：完整卡片以小角度倾斜浮在背景上，文字层与卡框稳定不参与视差。
4. **`before` 版**层距更散、错位更夸张；`after` 版（当前默认）收紧一档。

对应实现：

| 官方特征 | 代码位置 |
|---|---|
| 全卡面箔光 + 斜向扫光带 | `film/sweep/spectrum` 原系数保留；新增 `glintBand = exp(-axis²/(σ²·2.6))`（轴向 0.72/0.45）与 `glintCore`，`glintCenter = 0.5 + uView.xy·uGlintRange`，色散 `phase + r·1.2` |
| 分层空间重影 | `subjectDepth / lineDepth / effectsDepth / backgroundDepth` 四套独立深度；`uGhost` 沿视线错开一份主体 alpha；`uRelief` 主体轻微前凸；文字层不做视差 |
| 卡片倾斜构图 | `cardUv()` 由 `uView` 生成近似单应变换；`uCardMode` 可切回全屏铺满；卡片外用暗化背景延伸 |
| 静止帧干净 | 所有主相位由 `uView` 驱动，`uTime` 只推星点；`uTrail` 由角速度动态置零 |

此外补上**时间残影动效**：仅在视角快速变化时，用 3 次递减 tap 沿 `uTrailVec`
方向叠加**主体轮廓之外**的彩虹残像（`ghostEdge = max(0, ts.a - baseA)`），
避免整块主体过曝；静止时自动归零，因此不破坏官方静态观感。
`?trail=1` 可固定开启验收，`?finish=3` 可切到演示同款烫金质感。

## 5. 可行性评估

### 5.1 性能

| 指标 | 估算 | 判断 |
|---|---|---|
| Draw call | 1 | 极低 |
| 片元量 | 390×844 CSS × 1.75 DPR ≈ 683×1477 ≈ **1.0M 片元/帧** | 60fps ≈ 60M 片元/s，中端 SoC 可承受 |
| 每片元纹理采样 | 5~6 次（含 ghost 重采样） | 可接受，`LINEAR` + `CLAMP_TO_EDGE` |
| 数学开销 | 2 次 `sin/cos`、1 次 `exp`、1 次 `length` | 主要成本；必要时把 `exp` 换成 `smoothstep` 近似 |
| GPU 纹理内存 | 5 × 1024×1536×4B ≈ **30 MB** | 偏高，见难点 #7 |
| 传感器开销 | 60Hz、O(1) 滤波 | 可忽略；隐藏时停止 |
| 静止功耗 | 12fps + 传感器降频 | 远低于视频壁纸 |

结论：**Web 版性能路线可行**，瓶颈不在算力而在「常驻功耗」与「纹理内存」，两者都已有对策。

### 5.2 兼容性

| 环境 | 传感器通道 | 渲染 | 能否设为**系统**壁纸 |
|---|---|---|---|
| Android Chrome（HTTPS） | 原生 `RelativeOrientationSensor` → `deviceorientation` | WebGL1 | ❌ 需原生壳或第三方「网页壁纸」App |
| iOS Safari（HTTPS + 授权） | `deviceorientation` + `requestPermission()` | WebGL1 | ❌ 无公开 API |
| Android 原生 Live Wallpaper | `SensorManager.TYPE_GAME_ROTATION_VECTOR` | GLES20 | ✅ 官方支持 |
| 微信小程序 | `wx.startGyroscope` / `wx.onGyroscopeChange` | 小程序内预览 / 导出静态图 | ❌ |
| 桌面浏览器 | 指针 / 自动巡游 | WebGL1 或 CSS-3D | — |

Generic Sensor API 目前**只有 Chromium 实现**（Chrome 67+、Edge 79+、Android WebView 67+），
Firefox 与 Safari 均未实现；因此主通道必须是 `deviceorientation`。

### 5.3 系统壁纸 / 小程序的硬限制（必须提前对齐预期）

- **Android**：可以。`WallpaperService.Engine` 拿到 `SurfaceHolder`，用 EGL14 绑定
  `GLES20` 渲染、用 `SensorManager` 取姿态即可。`android/` 目录给出了骨架：
  传感器→四元数→`uView` 的链路已完整实现，EGL 绑定可用 `GLWallpaperService` 基座补齐。
  注意 `onVisibilityChanged(false)` 必须停传感器与渲染，否则系统会判定为耗电应用。
- **iOS**：**不可以**。Apple 没有向第三方开放设置锁屏/主屏壁纸的 API（无
  `WallpaperManager.setBitmap()` 等价物），也不允许第三方代码在锁屏持续运行动画。
  可行替代只有：导出带景深信息的 HEIC / Live Photo / 静态图到相册 → 引导用户到
  「设置 → 墙纸」手动设置；实时体感效果只能在 App 前台体验。iOS 16+ 进一步收紧了
  锁屏常驻动画。
- **微信小程序**：**不可以设为系统壁纸**，且小程序不能后台常驻渲染。
  `wx.onGyroscopeChange` 返回的是**角速度 (x/y/z, rad/s)** 而不是绝对姿态，
  要做视角跟随必须自行积分并配合 `wx.onAccelerometerChange` 做重力校正，漂移明显；
  `interval` 三档 `game≈20ms / ui≈60ms / normal≈200ms`，`game` 档才够跟手。
  因此阶段二小程序的定位应是「**生成器 + 相册保存**」，不是「实时壁纸」。

> 这三条限制直接决定了产品形态：**真·动态壁纸只能走 Android 原生 / 网页壁纸 App；
> 微信小程序负责生成与付费，交付物是高精度静态图或短视频。**

## 6. 难点与应对

| # | 难点 | 应对 |
|---|---|---|
| 1 | 权限与安全上下文；HTTP 下事件静默失效 | 手势内 `requestPermission()`；`tools/serve.py` 自动签证书；`adb reverse` + localhost；生产部署到公网 HTTPS；UI 明确提示失败原因 |
| 2 | iOS/Android 坐标系、横竖屏、轴符号差异 | `deviceTiltToScreen` 屏幕角补偿 + 校准按钮 + `invertX/Y` 开关；四元数通道优先；真机列表逐项标定 |
| 3 | alpha 跨圈跳变、万向锁、磁力计漂移 | `angleDelta` 折回 ±180；四元数通道规避奇点；alpha 仅以 0.12 权重参与横向；Android 原生改用 `GAME_ROTATION_VECTOR`（不含磁力计） |
| 4 | 传感器噪声与手持抖动 | 帧率无关 EMA + 死区 + 静止检测；进阶可换互补滤波 / 卡尔曼 / 临界阻尼弹簧 |
| 5 | 长时间常驻耗电 | 静止 12fps、DPR≤1.75、hidden 停帧、隐藏停传感器、事件节流；不在事件回调里做渲染 |
| 6 | WebGL 不可用 / 老 WebView | CSS-3D 分层 + 径向渐变高光兜底（`createCssFallback`），仍有随动效果 |
| 7 | 5 张 1024×1536 RGBA 占 30MB GPU 内存 | 演示素材可降到 768×1152（约 17MB）；正式产品改用 ASTC/ETC 压缩纹理或按 `maxTextureSize` 动态降采样 |
| 8 | `file://` 下 `texImage2D` 跨域失败 | `standalone.html` 把 PNG 内联为 data URI；ESM 动态 import 在 file 协议下自动禁用 |
| 9 | 系统壁纸 Surface 绑定 | Android 用 EGL14 绑定 `WallpaperService` 的 Surface（或 `GLWallpaperService` 基座）；iOS / 小程序明确放弃系统壁纸路径 |
| 10 | 视觉「像循环视频」而非箔 | 所有主相位由 `uView` 驱动，`uTime` 只推星点；不把彩虹烘焙进画稿（RuiC 的明文约束） |
| 11 | 隐私合规 | 姿态数据只在端内参与渲染，不采集、不上传、不落盘；权限说明写到 UI 上 |
| 12 | 自动化证明「闪光真的跟随」 | `?view=` 固定视角 + headless 截图做像素对比；`__holoWallpaper.getState()` 断言 uView 变化 |
| 13 | GLSL ES 保留字导致着色器静默编译失败、页面悄悄退回 CSS 兜底 | 实测踩坑：`half` 是保留字，改名 `halfSize`；编译/链接错误写入 `document.body.dataset.glError`，无头浏览器用 `--dump-dom` 可立即发现，避免「看起来能跑其实没走 WebGL」 |
| 14 | Windows 本地服务把 `.js` 返回 `text/plain`，ESM 被严格 MIME 检查拒绝、页面停在初始遮罩 | `tools/serve.py` 的 `HoloHandler` 显式固定 `.js/.mjs -> text/javascript`；ESM 入口已实测与单文件版像素完全一致（diff 0.00） |
| 15 | 照片类素材闪光过曝、把重影吃掉 | 照片测试注入 `glintGain 0.72 / foil 0.60`，同时加大 `ghost 0.88 / trail 1.5 / lineDepth -0.06`；残影只叠加轮廓差异 `max(0, ts.a - baseA)`，不叠整块主体 |

## 7. 阶段一验收标准（通过这些后才进入阶段二）

1. **离线**：`npm test` 全绿（角度跨圈、四元数、阻尼收敛、视差公式、着色器契约、文件完整性）。
2. **素材**：RuiC 的 `validate_assets.py .` 通过，5 层同画布、真 alpha、白底黑线。
3. **渲染**：headless Chromium 分别在 `?view=-0.55,0` 与 `?view=0.55,0` 截图，
   高光中心与视差方向应有可观测位移；无 WebGL 报错、无资源 404。
   `tests/verify_render.py --capture` 已把这条做成可复现的自动断言。
   **本机构建实测（2026-11-12，headless Edge + SwiftShader，390×844）**：
   中央 350×500 区域平均像素差 42.46；左半区 Δ = −32.37、右半区 Δ = +20.39，
   方向性差值 +52.76；高亮重心右移 36.4 px —— 闪光确实由 `uView` 驱动。
   ESM 主入口经 HTTP 与单文件版像素差 0.00。
4. **交互**：4 种质感、5 个滑块、卡片/全屏模式、校准按钮、面板收起均生效。
5. **照片端到端测试**：`tools/make_photo_wallpaper.py` 用真实照片生成
   `examples/photo-test/photo-wallpaper.html`；5 层素材通过 RuiC 体检，
   左/右倾平均像素差 20.22，残影开/关局部最大差 188.3，过曝饱和像素仅 2.4%，
   照片边缘双层彩色重影清晰可见。
6. **真机**：iOS Safari 授权通过 / 拒绝降级；Android Chrome 四元数通道；左右倾、
   前后倾、横屏 90°、后台切回、静止降帧；各状态无白屏、无倒转视差。
7. **功耗**：静置 5 分钟无异常发热，fps 稳定在 12 左右；倾斜时回到 60。

未通过任一项则先修阶段一，不启动阶段二。
