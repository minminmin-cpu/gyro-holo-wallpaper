## 2. 完整架构

### 2.1 一个 APK，两个组件

| 组件 | 职责 |
|---|---|
| `MainActivity`（Jetpack Compose） | 上传照片 / 提示词输入、模型配置、生成、预览、调参、Profile 管理、设为壁纸 |
| `HoloWallpaperService : WallpaperService` | EGL14 + GLES20 实时渲染 + `SensorManager.TYPE_GAME_ROTATION_VECTOR` 驱动视角 |

默认**同进程同 UID**，不需要跨进程 IPC；`SharedPreferences` 与 `files/` 可直接共享。
用 `ACTION_CHANGE_LIVE_WALLPAPER` + `EXTRA_LIVE_WALLPAPER_COMPONENT` 跳系统确认页，
用户确认后系统接管服务，**App 退出甚至被杀，壁纸照常运行**。

### 2.3 组件清单

| 类 / 模块 | 输入 | 输出 | 关键点 |
|---|---|---|---|
| `ModelProvider` / `ProviderRegistry` | 用户填写的 endpoint、Key、模型名、能力 | 已加密持久化的配置 | AndroidKeystore AES-GCM；多 Provider 并存 |
| `CardDesignClient` | 照片 + 设计描述 + 用户自配 Provider | 白名单 `CardDesign` JSON | 仅 Chat 协议；视觉输入含照片 data URI；失败不落 Profile |

| `EglRenderer` | 3 张纹理 + uniforms | 一次 `glDrawArrays` | GLSL ES 1.00，GLES2 直接编译 |
| `AttitudeSource` | `TYPE_GAME_ROTATION_VECTOR` | 相对四元数 | 校准 + 共轭，与 `src/math.js` 逐行对应 |
| `DampedView` | 目标倾角 + dt | `uView` | `1-exp(-dt/τ)` 帧率无关阻尼 |

### 2.4 数据流

```
照片 + 设计描述
   → 用户自配文本/视觉 Chat 模型规划设计 JSON（仅视觉协议发送照片）
   → 严格校验设计字段、枚举和范围
   → 原始照片本地合成 5 层 + Canvas 绘制设计文字、配色、边框与装饰
   → Profile 落盘（完全离线）
   → 写 active_profile_id
   → ACTION_CHANGE_LIVE_WALLPAPER 让用户确认
   → Engine 读 Profile，加载纹理，传感器驱动 uView，实时渲染到主屏
```

Profile 目录：

```
files/profiles/<uuid>/
  ├── card-config.json    # subjectDepth / ghost / trail / finish / 模型 ID
  ├── subject.png         # 圆角羽化 RGBA
  ├── background.png      # 模糊暗化，不透明
  ├── text.png            # 真 alpha
  └── meta.json           # 提示词、来源类型、生成时间
```

## 3. 实现方式（逐层说明）

### 3.1 EGL14 绑定 WallpaperService 的 Surface

`WallpaperService` 没有 View 层级，`GLSurfaceView` 无法直接附着，必须自己建 EGL：

1. `eglGetDisplay(EGL_DEFAULT_DISPLAY)` → `eglInitialize`
2. `eglChooseConfig`（RGBA8888、无 depth/stencil，壁纸不需要深度缓冲）
3. `eglCreateContext(display, config, EGL_NO_CONTEXT, {EGL_CONTEXT_CLIENT_VERSION, 2})`
4. `onSurfaceCreated`：`eglCreateWindowSurface(display, config, holder.surface, ...)`
5. `eglMakeCurrent(display, surface, surface, context)`
6. 每帧 `glDrawArrays` → `eglSwapBuffers(display, surface)`

`onSurfaceChanged` 需销毁并重建 window surface + `glViewport`；
`onSurfaceDestroyed` 释放纹理 / program / surface / context / display。
可直接以 [`hanschencoder/GLWallpaperService`](https://github.com/hanschencoder/GLWallpaperService)
为基座省掉样板代码。

### 3.2 GLSL 复用与防漂移

第一阶段的 `src/holo-shader.js` 已经是 **GLSL ES 1.00**，GLES2 可直接编译：
`parallax / spectrum / film / sweep / glintBand / glintCore / cardUv / uTrail` 全部保留，
系数一个都不改。用 `tools/sync_shader.py` 把 `FRAGMENT_SHADER` / `VERTEX_SHADER`
导出成 `android/app/src/main/assets/shader/holo.frag` / `.vert`，**只改 JS 源再同步**，
避免两份 shader 漂移。

> 已踩过的坑：`half` 是 GLSL ES 保留字，作变量名会导致编译失败并静默退回降级渲染。
> 同步脚本应带一次编译期校验。

### 3.3 纹理与 uniform

- 3 张纹理（`tSubject` / `tBackground` / `tText`）：`BitmapFactory.decodeFile` →
  `GLUtils.texImage2D`，`CLAMP_TO_EDGE` + `LINEAR`，不生成 mipmap。
- **不再生成 `lineart.png`**：线稿边缘在片元着色器里对 `tSubject` 做 4 次邻域采样求近似
  Sobel（或 GLES3 用 `dFdx/dFdy`），省一张 6MB 纹理和一整趟 CPU 卷积。

> **M1 取舍**：为保证与第一阶段及官方演示的视觉完全一致，M1 先按原契约加载
> **5 张纹理**（`android/app/src/main/assets/demo/`），GLSL 由 `tools/sync_shader.py`
> 零改动同步；「减到 3 张 + GLSL 求导」作为性能优化留到 M2 与端上拆层一起做。
- uniform 映射：`uView` ← `DampedView`；`uTime` ← 累计秒（只推星点）；
  `uAspect` ← `[w/max(w,h), h/max(w,h)]`；`uFoil/uScale/uDepth/uBgDepth/uFxDepth/
  uFinish/uGlintGain/uGlintSigma/uGlintRange/uGhost/uCardMode/uCardScale/uTiltGain/
  uRelief/uLineDepth/uTrail/uTrailVec` ← `card-config.json`。

### 3.4 传感器 → uView

```
registerListener(TYPE_GAME_ROTATION_VECTOR, SENSOR_DELAY_GAME)   // 无需权限、不受磁干扰
  → q = [x,y,z,w]
  → baseQuat 校准（用户手持姿态即中性点）
  → rel = inverse(baseQuat) * q
  → rotate([0,0,1], conjugate(rel))      // 对齐 RuiC 的 root.matrixWorld.invert()
  → DampedView.step(dt)                  // a = 1-exp(-dt/0.11)，含死区
  → uView = normalize(tx, ty, 1)
```

`android/HoloWallpaperService.kt` 已给出完整的四元数乘/共轭/旋转实现，与
`web/src/math.js` 逐行对应；`Choreographer` 每帧调用 `onFrame()`。
手机静置时传感器几乎不变，保留 Web 版的 `autoTour()` 做极缓慢巡游作为兜底，
检测到姿态变化再切回传感器驱动。

### 3.5 帧循环与省电

- `Choreographer` 驱动；静止 12fps、倾斜时 60fps；DPR ≤ 1.75
- `onVisibilityChanged(false)` 注销传感器 + 停渲染；`isPreview()` 降帧且不弹权限、不联网
- 低端机素材降到 768×1152；暗色 / OLED 友好
- 厂商省电白名单只能引导用户开启，UI 需明确说明

### 3.6 端上拆层（不依赖模型）

| 层 | 做法 |
|---|---|
| `background` | 原图 cover 铺满 → 降采样再放大做高斯近似（或一次 GPU 模糊 pass）→ 暗化 + 径向渐变 |
| `subject` | 原图 contain 居中 → 圆角矩形 mask + 轻羽化 → 真 RGBA |
| `text` | `Canvas.drawText` + 系统字体画卡框、标题、编号、稀有度 → 透明 ARGB_8888 |

第一阶段的照片测试（`examples/photo-test/`）已验证这三张就能出完整闪光重影效果。
`ExifInterface` 必须先校正方向——测试照片原本就是横躺的。
GPU 纹理内存从 5 张 ~30MB 降到 **3 张 ~18MB**。

### 3.7 设为壁纸

```kotlin
val intent = Intent(WallpaperManager.ACTION_CHANGE_LIVE_WALLPAPER).putExtra(
    WallpaperManager.EXTRA_LIVE_WALLPAPER_COMPONENT,
    ComponentName(this, HoloWallpaperService::class.java)
)
startActivity(intent)
```

Manifest 需 `<service android:name=".wallpaper.HoloWallpaperService"
android:permission="android.permission.BIND_WALLPAPER" android:exported="true">`
与 `<meta-data android:name="android.service.wallpaper" android:resource="@xml/wallpaper"/>`。

## 4. 模型配置层（可自定义添加，完全 BYOM）

### 4.1 数据模型

```kotlin
data class ModelProvider(
    val id: String, val displayName: String,
    val protocol: Protocol,        // OPENAI_CHAT_TEXT / OPENAI_CHAT_VISION
    val baseUrl: String, val modelId: String,
    val apiKeyCipher: ByteArray,   // AndroidKeystore AES-GCM，禁止明文
    val capabilities: Set<Capability>,   // DESIGN_JSON / VISION
    val timeoutSec: Int = 60, val maxConcurrency: Int = 2,
)
```

**本项目不托管任何模型、不代理任何请求、不向服务端上传 Key**。用户填自己的 endpoint 与 Key，
App 直连。因此也没有账号体系、没有额度系统、没有遥测。

### 4.2 协议适配

| 协议 | 适配方式 |
|---|---|
| `OPENAI_CHAT_TEXT` | `POST {baseUrl}/chat/completions`，仅发送设计描述，返回设计 JSON |
| `OPENAI_CHAT_VISION` | 同一 Chat 路径，发送照片 data URI + 设计描述，返回设计 JSON |

不预置模型、地址或密钥。旧协议配置仅保留供用户迁移，使用前必须重新选择 Chat 协议保存。模型不能输出图片或资源地址，客户端不会下载响应资源。

### 4.3 「测试连接」与密钥安全

- 测试连接仅 `GET {baseUrl}/models`，只验证地址和鉴权可达，不验证设计 JSON 或视觉能力；实际创作失败直接显示原因，不静默回退。
- Key 用 `AndroidKeystore` AES-GCM 加密后落 Room；不进日志、不进云备份
  （`dataExtractionRules` 排除）、不随任何 Issue/日志上报。
- 仅 `INTERNET` 权限用于**生成阶段**；壁纸服务永不联网。

## 5. 多模态能力提示（精确口径）

| 能力 | 是否必需 | 说明 |
|---|---|---|
| `DESIGN_JSON` 卡片设计 | 必需 | 标题、副标题、典藏名、编号、配色、字号、对齐、边框、装饰与景深参数 |
| `VISION` 画面理解 | 视觉协议必需 | 接收照片 data URI，根据照片内容规划卡片；文本协议仅按描述规划 |

`CardDesign` 对顶层和嵌套对象均采用精确字段白名单；颜色限定 `#RRGGBB`，文案限定长度，排版与装饰采用枚举，数值限定范围。拒绝额外字段、资源路径、链接、图片和无效 JSON。设计中的每个字段分别影响本地纹理或 RuiC `card-config.json`。照片、文字、线稿与装饰全部端上生成，五层统一 1024×1536，主体/文字/装饰保留真实 alpha，背景不透明；线稿由完成布局的主体提取，避免错位。

## 7. 风险与限制

| 风险 | 说明 | 应对 |
|---|---|---|
| 锁屏动态壁纸 | Live Wallpaper 作用范围由 Launcher/SystemUI 决定，多数 ROM 只在主屏动态 | 卖点只承诺主屏；锁屏提供导出高光静态帧；`FLAG_LOCK` 尽力而为 |
| 厂商省电策略 | 可能杀壁纸服务或冻结传感器 | 引导白名单；Profile 离线可用，服务重启自恢复 |
| 自定义模型不可控 | 地址错误 / 配额耗尽 / 设计 JSON 不合约 / 证书异常 | 连接检查 + 严格校验 + 明确报错，不生成替代结果 |
| 密钥泄露 | 明文存储、日志、云备份 | Keystore 加密 + 禁日志 + 排除备份 |
| **开源合规** | 误传私人照片或上游 demo 素材；遗漏 MIT/BSD 声明 | `.gitignore` 强约束 + `THIRD_PARTY_NOTICES.md` + 发布前 `git status` 复核 |
| 两份 shader 漂移 | Web 与 Android 各改各的 | 单一源 `src/holo-shader.js` + 同步脚本 + 编译校验 |

| **M4** | **开源发布**：LICENSE / 声明 / CI 签名构建 / GitHub Release APK / 英文 README | tag 触发构建成功、APK 可安装、SHA-256 可校验、仓库无私人素材与密钥 |

> M1 的算法风险为零（第一阶段 14/14 单测 + 6/6 渲染验收已覆盖 GLSL 与传感器数学），
> 主要工作量在 EGL 绑定、纹理加载与生命周期。
